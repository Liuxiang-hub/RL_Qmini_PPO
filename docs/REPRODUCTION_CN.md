# Qmini 项目中文完整复现流程

本文档给出从真机数据采集、自动 PD 辨识、仿真训练到 ONNX 真机部署的完整顺序。复现时不要跳过“接口与安全门禁”，否则即使策略网络本身正确，也可能因为关节符号、URDF 零位或 IMU 坐标系不一致而导致真机异常。

## 1. 硬件与软件

- Qmini 双足机器人，10 个受控关节；
- H30 IMU，实测输出约 200 Hz；
- 树莓派 Ubuntu 22.04 arm64；
- GPU 服务器 RTX 4090；
- Python 3.8、PyTorch 2.0.0+cu117、Isaac Gym Preview 4；
- 训练控制周期 `15 ms`，仿真物理步长 `1 ms`，每次动作重复 15 个物理步。

## 2. 数据采集

### 2.1 安全准备

1. 将机器人吊起，确保双脚完全离地；
2. 检查四路电机串口和 IMU 串口；
3. 确认急停有效；
4. 只对一个关节施加小幅正弦目标，其他关节保持安全参考位；
5. 记录目标角、原始实际角度和原始速度，不使用后处理后的“美化数据”。

### 2.2 采样协议

每个关节采集 `0.5 Hz`、`1.0 Hz` 和 `1.5 Hz` 三组响应，控制周期固定为 `0.015 s`。其中：

- `0.5 Hz + 1.5 Hz`：用于参数选择；
- `1.0 Hz`：完全留出，只在所有人工/自动参数冻结后评估。

日志至少包含：测试关节编号、频率、阶段、10 维目标角、10 维原始关节角和 10 维原始关节速度。

## 3. 模型对齐

### 3.1 URDF

本项目修正的是髋关节 `origin rpy`：

| 关节 | 修改前 | 修改后 |
|---|---|---|
| left hip yaw | `0 0 0.40` | `0 0 0.55` |
| left hip roll | `0 0 0` | `-0.25 0 0` |
| right hip yaw | `0 0 -0.40` | `0 0 -0.55` |
| right hip roll | `0 0 0` | `0.25 0 0` |

这不是修改关节轴向。`axis`、`origin xyz`、网格、质量和惯量保持不变。

最终 URDF SHA256：

```bash
sha256sum assets/q1/urdf/q1_hip_aligned.urdf
# ac50da103e32e71122209fbfcbd22b907af246c4f042dca004e3b0459ebc6bbe
```

### 3.2 参考站姿与限位

训练侧参考/复位站姿：

```python
[0.55, 0.25, -1.35, 1.2, -1.1,
 -0.55, -0.25, 1.35, -1.2, 1.1]
```

关节限位必须和真机软件使用同一顺序、方向和单位。髋侧摆限位为左侧 `[0, 0.6]`、右侧 `[-0.6, 0]`。

### 3.3 PD 力矩公式

仿真中的阻尼项必须是增益与速度的乘积：

```python
tau = kp * kp_rand * (q_target - q) - kd * kd_rand * qd
```

不能写成 `+ kd - kd_rand * qd`，否则 `kd` 会错误地变成恒定力矩偏置。

## 4. 自动 PD 辨识

对每个关节并行生成 `(Kp, Kd, delay_steps)` 候选，在固定基座 GPU PhysX 中回放相同目标轨迹。目标函数为 0.5 Hz 与 1.5 Hz 位置 RMSE 的均方根：

```text
J = sqrt((RMSE_0.5^2 + RMSE_1.5^2) / 2)
```

推荐流程：

1. 公共粗搜索：`Kp ∈ [10, 400]`、`Kd ∈ [0.01, 20]`、延迟 `0–8` 个周期；
2. 在最优点附近做细搜索；
3. 如果最优点落在硬边界，预先规定扩大范围后重跑；
4. 参数冻结后才加载 1.0 Hz 留出集；
5. 输出每关节 JSON、候选 CSV、拟合图和输入文件哈希。

最终三参数自动辨识结果如下：

| 关节 | Kp | Kd | 额外延迟 |
|---|---:|---:|---:|
| left_hip_yaw | 66.25 | 2.0239 | 0 ms |
| left_hip_roll | 500.00 | 32.5000 | 0 ms |
| left_hip_pitch | 63.75 | 0.0933 | 0 ms |
| left_knee | 500.00 | 32.5000 | 0 ms |
| left_ankle_pitch | 46.25 | 2.6169 | 0 ms |
| right_hip_yaw | 58.75 | 1.1565 | 0 ms |

| right_ankle_pitch | 48.75 | 2.9907 | 0 ms |

这些是“有效闭环参数”，用于匹配当前机器人、负载、驱动器和控制周期下的动态响应；不能把驱动器接口中的数值直接解释为严格 SI 单位下完全等价的物理刚度。

## 5. 人工对比实验

为保证公平，人工和自动方法都只调 `Kp`、`Kd`、延迟三个参数。人工操作者只能查看 0.5 Hz 和 1.5 Hz 曲线，不能查看 1.0 Hz 结果。每次候选都记录：

- 关节、Kp、Kd、延迟；
- 选择理由；
- 两个拟合频率的 RMSE；
- 操作时间；
- 数据和 URDF 的 SHA256。

最后一次确认值作为冻结的人工参数，然后统一运行 1.0 Hz 留出集评估：

```text
人工平均 RMSE = 0.006521304883 rad
自动平均 RMSE = 0.003683285625 rad
相对误差降低 = (人工 - 自动) / 人工 = 43.5192%
```

完整逐关节数据见 `docs/results/heldout-comparison.csv`。

## 6. 训练前门禁

训练前至少完成：

- URDF 哈希正确；
- 关节顺序、左右腿、正负方向一致；
- 参考站姿及 `±0.05 rad` 扰动不越限；
- 32 个无随机化环境纯 PD 保持 10 秒；
- 存活率 100%，无 NaN/Inf、非法碰撞和持续扭矩饱和；
- H30 IMU 平放、前倾、左倾方向正确；
- 软件链路中只保留一层 IMU 坐标变换。

## 7. PPO 训练

```bash
export PATH=/path/to/isaac-env/bin:$PATH
export TORCH_EXTENSIONS_DIR=/data/torch-extensions

python train.py \
  --config BIRLPhysicalPD \
  --name qmini_h30_pd_hip_aligned_seed20260927 \
  --num_envs 20480 \
  --max_iterations 5000 \
  --seed 20260927
```

监控内容：唯一训练进程、GPU 利用率/显存/温度、最新迭代、奖励、KL、价值损失、策略损失、checkpoint 更新时间、NaN/Inf/CUDA/OOM 和磁盘空间。

恢复训练时必须加载完整 checkpoint（Actor、Critic、优化器和迭代号），并保证最终停在第 5000 轮；不要同时启动第二个训练进程。

## 8. 仿真评估

先关闭所有随机化做确定性回放：

```bash
python play.py --name qmini_h30_pd_hip_aligned_seed20260927 \
  --num_envs 1 --time 20 --render
```

依次测试：零速度站立、`0.30 m/s` 前进、`0.50 rad/s` 转向。随后开启训练时随机化，让随机指令每段持续 20 秒，确认策略不是只记住单一命令。

## 9. ONNX 导出与静态验证

```bash
python export_pt2onnx.py --name qmini_h30_pd_hip_aligned_seed20260927
```

导出后检查：

- 输入名称 `input`、形状 `1 × 129`；
- 输出名称 `output`、形状 `1 × 12`；
- PyTorch 与 ONNX 输出差异在浮点误差范围；
- 输入/输出全部有限；
- 将同一文件复制到树莓派后，使用真机 C++ ONNX Runtime 再运行至少 1000 次静态推理；
- 记录模型 SHA256，部署前备份原 `policy.onnx`。

## 10. 真机与网页控制

推荐状态机：

```text
开机高阻尼保护 -> Ready -> Stand -> RL
       ^            |        |      |
       +------------+--------+------+  急停/取消
```

- Ready、Stand、RL 之间通过手柄或网页事件切换；
- 摇杆归零时 RL 策略接收零速度命令并原地站立；
- 急停返回高阻尼安全状态，不应直接发送 `Kp=0, Kd=0`；
- 网页必须发送递增 sequence 和持续心跳；
- 看门狗超时后将速度命令平滑清零并记录原因；
- 每 15 ms 记录时间、模式、控制源、网页 sequence、网页命令、手柄命令、IMU 和看门狗年龄。

真机首次运行必须在吊架上依次验证 Ready、Stand、零速 RL，再逐渐增加前进和转向命令。

## 11. 已知限制

- 足端在光滑地面上会打滑，高摩擦地面效果明显更好；
- 固定基座关节辨识主要覆盖执行器闭环动态，不能完全替代全身接触参数辨识；
- 不同机器人、负载、电源电压和驱动器固件下应重新采集数据，不能直接照搬参数；
- Isaac Gym Preview 4 与官方早期 Preview 3 环境并非完全等价。
